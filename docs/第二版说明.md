# 第二版开发与升级说明

## 1. 本次实现

第二版沿用Python、RDFLib、Fuseki、FastAPI、Vue和Leaflet，不新增推理引擎或历史数据库。

- 默认模拟3架无人机，配置初始化为2处阵地。
- 每架无人机每次有效新观测，对每个已配置阵地分别生成Assessment（评估记录）。
- Observation（观测记录）保存位置、速度、来源、时间；评估关联观测与规则。
- 地图支持多标记选择、选中阵地参考圈、距离排序与选中目标连线。
- 评估依据面板可锁定一条结果，显示观测、规则版本和历史阵地坐标。
- 中文本体列表、原始定义TTL、选中目标关联TTL均支持新模型。
- 选中目标历史可播放、暂停和拖动，按时间查询所有目标的最近观测，提供轨迹参考线。
- 配置界面维护1～10处阵地、距离阈值、过期时间、每目标10～1000条历史记录。

## 2. 业务语义

### 为什么增加评估记录

一架无人机距一号阵地80米、距二号阵地500米，需要两条独立评估；不能只在无人机上堆两个距离和两个等级而失去对应关系。

每条评估保存：无人机、阵地标识、观测标识、规则标识、水平距离、等级、时间，以及当时阵地名称和坐标。

规则快照保存高/中/低阈值和观测有效时长。规则版本由完整配置内容生成，所以配置变化后可区分新旧结果。Python继续计算和判断，本体表达关联与结果。

### 配置什么时候生效

保存配置不改写已有评估。下一条有效新观测使用新配置，旧评估继续对应旧版本。界面等待期间提示“旧配置”。删除某阵地后实时列表不再显示它，历史仍可看到该阵地的旧评估。

### 回放语义

前端以选中目标的保留观测作为时间轴；每帧通过at参数查询历史中各目标在该时刻之前最近的观测，而不是拿当前坐标假装历史位置。

实时接入在回放期间继续。回放不写数据库、不重新发消息、不重新计算历史等级。历史阵地坐标、规则阈值从评估快照读取。不同目标在某帧可能对应不同观测时间或规则版本，具体以评估面板为准。

地图上阵地点位来自该帧保留的评估快照；连线端点和解释面板优先使用选中评估的实际快照坐标。圆圈是距离范围参考，不等同于多边形防区判断。

## 3. 第一版升级

升级前保留代码版本及数据库备份。停止应用写入后再备份TDB2，不能在数据库正在写入时直接复制其目录。

在项目目录可按以下顺序做备份（需要本机tar和足够磁盘空间）：

```bash
mkdir -p backups
# 停止模拟与应用，再停止Fuseki，保留容器和数据卷
docker compose --profile demo stop simulator app fuseki
# compose容器处于停止状态时可以复制其数据目录
docker compose cp fuseki:/data ./backups/fuseki-data-before-v2
cp .env ./backups/env-before-v2
```

备份目录首次使用即可；已有同名备份时请另选目录，避免混入旧文件。若未启动过第一版服务，则无需执行数据库备份。

随后拉取代码、构建和启动：

```bash
git pull --ff-only
docker compose build
docker compose up -d --wait
docker compose --profile demo up -d --force-recreate simulator
```

第二版启动会自动识别第一版没有latestObservation的目标，将其最新位置迁移为观测并按当前配置补齐独立评估。不会凭空补造之前未存储的轨迹。

旧版客户端接口返回结构发生变化：position改为positions数组；目标的距离/等级从target.assessments读取。前后端需一起更新，不要只替换一端。

新增文件不会触碰Mac Docker Desktop的代理配置。此前TLS超时问题需要继续解决本机网络，升级代码本身不能保证构建连接恢复。

## 4. 历史保留与部署边界

- 默认每目标300条，1Hz约5分钟；调整到更小数量会清理较旧观测和关联评估。
- 历史不是永久审计，播放期间最早记录也可能被后台清理；接口会明确返回不存在，前端保留错误提示。
- 不同无人机独立清理，保留时长受各自上报频率影响。
- Fuseki仍是事实数据来源，不增加独立SQLite副本；大规模长期历史需要后续设计。
- 单应用实例、单worker；当前进程内锁不支持多个后端实例并发配置管理。
- 配置界面没有权限体系，部署应限制访问范围。
- 地图和评估是演示性距离分析，不包含黑飞合法性判断、意图判断和综合威胁评分。

## 5. 后续建议

先通过演示检查“目标—观测—评估—阵地—规则”的关联是否便于理解，再考虑真实设备适配、独立历史存储、权限、性能和更复杂的业务指标。推理引擎不是本版依赖。
