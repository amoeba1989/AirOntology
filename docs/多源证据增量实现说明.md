# V2.3 多源观测与本体职责边界

本增量承接《多源观测与本体职责边界：开发交接说明》，保留已有态势大屏和智能问答交互，增加证据登记与学习区。技术解释见[本体技术栈与代码实现指南](本体技术栈与代码实现指南.md)。

## 已实现

- 统一登记雷达、无线电、摄像头、红外设备与原始观测。来源声明、观测时间、服务端接收时间、坐标系、位置及误差、质量、特征、原始引用与模拟标记均保留；原始引用仅存文本，不抓取链接。
- 原始观测独立于已有目标航迹。检出不会自动创建无人机实例；观测相近不会自动认定同一目标。
- 关联、无人机识别、异常闯入条件分别登记方法、版本、输入观测、前置判断、条件、不确定性及时间。仅支持疑似、待核实、证据不足、冲突四种未确认状态，不接受 confirmed 状态。
- 观测、判断、区域与授权不可覆盖；同编号同内容幂等。设备状态可由更新的声明替换，观测保留接收时的设备状态快照。
- 区分故障、状态未知、覆盖不足、正常但未检出、缺少近期观测。过期或无效正向输入会提示证据不足；未检出不推断目标不存在。
- 授权未知或有效期外保持未知；有授权声明与异常主张冲突时给出冲突提示。无授权声明本身也不确认异常闯入。
- 分数必须附含义，不作为概率；记录来源独立性说明，不按证据条数累计可信度。混合模拟与其他声明类型时提示冲突。
- 独立 RDF 命名图、OWL 术语、TTL 查看、SHACL 结构校验和中文词典实例查询。SHACL 不验证观测真实或算法性能，也不在每次写入时执行整图校验。
- 页面“本体学习 → 多源观测与证据”可查看设备、原始记录、三层判断、区域、授权，登记 JSON，显式导入模拟示例。每 5 秒在学习视图刷新；检出观测可作为独立原始点定位，不改变目标层。
- 原航迹模拟器明确声明模拟数据，目标详情和问答卡片显示数据声明；大模型只解释既有排序，不能融合、识别或提高结论确定性。

## 接入顺序

1. `GET /api/evidence/examples` 获取五类可编辑 JSON 模板。
2. `POST /api/evidence/devices` 登记来源设备；`POST /api/evidence/regions` 登记区域引用。
3. `POST /api/evidence/observations` 登记观测，或向 `counteruav/observation/raw` 发送相同 JSON。MQTT 主题支持 `MQTT_OBSERVATION_TOPIC` 配置；先登记设备。
4. 需要时登记 `authorizations`（授权声明），再登记 `judgements`（判断）。所有引用必须已存在，授权必须与疑似目标和区域匹配。
5. `GET /api/evidence` 看保守的当前可用性提示；`GET /api/evidence/ttl` 看事实图；`POST /api/evidence/validate` 执行结构校验。

设备或观测声明有效时长默认 60 秒，可填 2～3600 秒。示例到期后显示过期，需重新导入示例产生新记录，不伪装成实时真实设备。区域只保存几何引用，本版不计算包含关系。

## 资源与追溯限制

学习环境上限：设备 30 个、观测 200 条、判断 100 条、区域 20 个、授权 100 条。达到上限拒绝新增，不自动删除关联证据。模拟示例导入会预检查容量；跨多条 HTTP 存储请求并非整体事务，存储异常时可能部分写入，应先刷新核对。

业务航迹历史仍遵循原有保留策略；排序分析图只保留最近一次。上述证据保留不代表全项目永久审计。当前写入锁位于单个后端进程，适用于此学习演示的单进程部署；多写入进程需要进一步设计数据库级并发与容量约束。

## 尚未实现

没有选择或实现融合关联算法、无人机分类模型、区域包含算法或黑飞定性规则；没有独立验证集、误报漏报统计、概率校准或传感器真实性验证。本体约束和验证引用不能替代这些工作，也没有启用 OWL 推理。

后续应先确定设备协议与任务定义，再分别验证关联、身份和异常条件三层算法。每层保留验证版本、适用边界与失败场景，才能讨论提高结论确定性。
