# 态势大屏与合成航迹（演示版）

这一版将效果图落为交互界面，但不是图片贴图：左侧为阵地、已登记的部署设备和独立无人机目标；中央 Leaflet 地图显示实时观测点、已观测轨迹与选中阵地的距离分级圈；右侧解释当前距离、数据来源及 RDF/OWL 关系；底部显示已观测点时间线，可加载历史后进行回放。原本的本体学习、SPARQL、SHACL 与设备关系页面保留。

## 数据如何流转

1. `backend/app/demo_routes.py` 根据目标编号生成**可复现的合成航线**。四个轮换模板为接近－转弯－离开、近距离掠过－离开、周界巡航和交叉航线－返航。每个目标还具有固定种子的角度、比例、起始进度与速度差异；微小连续偏移使路径避免机械重复。封闭曲线在重复播放时不会跳到另一处。
2. `backend/app/demo_telemetry.py` 每帧按经过时间生成坐标、由位移计算速度与航向、生成模拟高度，并保留原有的雷达/干扰器登记与状态块。`simulator/main.py` 以 MQTT 发布设备登记和态势帧。
3. 后端仍由 `telemetry.py` 映射消息、`domain.py` 的 Python 地理距离计算生成每目标每阵地的独立评估，写入 RDF/Fuseki。前端仅展示已经上报的点，遇到断报不会画成连续轨迹；它不会把模拟航线写成本体因果规则。

所有路线、速度、高度、接收参数均属**合成演示数据**。轨迹形状只是用于教学的合理化示例，不是实际飞行记录、轨迹预测、雷达探测证明或干扰效果。接近阵地不等于黑飞、入侵或综合威胁；右侧等级只来自距离阈值。

## 本地或 ECS 演示

本地 Compose 默认 16 架目标、每 2 秒一帧；ECS 配置默认 10 架。先用 `docker compose up -d --wait` 启动基础服务，再用 `docker compose --profile demo up -d --force-recreate simulator` 启动或更新模拟器。页面打开“态势大屏”，观察 001 号接近、002 号掠过和其他目标的不同航路；点击对象后查看地图、距离卡、历史与本体事实。

小规格 ECS 或剩余磁盘较少时，在 `.env` 设置 `DEMO_TARGET_COUNT=8` 或 `10`，`DEMO_INTERVAL_SECONDS=2`，再重建并重启模拟器。数量越多，Fuseki 的历史写入和前端请求开销越高；历史每个目标默认保留 300 条，并非永久数据仓库。切换目标数会开启新的模拟运行；旧历史仍按原有有界保留策略处理。不要为清空间执行 `docker compose down -v`，那会删除 Fuseki 数据卷。

底图默认 OpenStreetMap。深色地图使用 CSS 调整现有瓦片亮度；如需效果图里的卫星影像，需先取得合规瓦片服务及授权，按 `.env` 的 `VITE_TILE_URL` 与 `VITE_TILE_ATTRIBUTION` 配置，并重建前端。瓦片坐标系须与现有 WGS84 坐标一致或做明确转换。

## 本体学习入口

- 右侧“本体关系”只展示明确登记的设备 `deployedAt` 阵地，以及无人机针对阵地的独立距离评估；**无人机没有 `deployedAt` 阵地**。
- TBox 展示类与属性的定义，ABox 展示最新对象和评估实例，TTL 显示其 RDF 文本；SPARQL 查询和 SHACL 校验仍在“本体学习”页。
- 可以从右侧“数据来源与处理”依次追踪模拟 MQTT 上报、Python 距离计算和 RDF 评估记录，理解数据、算法结果与本体事实各自的职责。
