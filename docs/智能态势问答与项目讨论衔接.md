# V2.2：项目讨论衔接与智能态势问答

> 后续本地开发版增加了三元组证据引用和高关注距离圈问题，当前行为请参阅[本体证据问答本地预览](本体证据问答本地预览.md)。本文保留 V2.2 的原始设计背景。

## 已衔接的讨论约定

本次通过项目历史检索衔接 2026-10-22 17:46、18:25、18:28 附近的无人机本体与智能体讨论。以下是用于开发的需求摘要，不是逐字聊天记录，也没有将另一段对话复制进当前聊天历史。

- 全屏数字大屏铺满浏览器；外部留白少，模块内部保留必要间距，少动画。
- AI 默认收起为小圆球，点击打开问答窗口。
- 首版仅提供现有本体和数据可以支持的预设问题，不显示缺数据的问题。
- 第一名、第二名、第三名等以格式化流式结果卡片展示；点击任一候选，在地图定位并高亮。
- 排序由本体策略约束，Python 负责确定性计算、排序和依据；大模型解释结果，不自由重排名，不重算，不改数据。
- 保留 MQTT、Python、RDF/OWL、RDFLib、Fuseki、SPARQL、FastAPI、Vue、Leaflet、Docker；首版不引入 Function Calling（函数调用）或自动 Action（业务操作）。

## 本次实现

默认进入“态势大屏”，布局使用浏览器可用宽高；点击“本体学习”回到包含词典、SPARQL、SHACL、TBox/ABox 与历史回放的完整工作台。右下角 AI 圆球打开问答面板，预设问题为：

1. 哪些无人机最需关注？
2. 哪些无人机距离阵地最近？

每次问题明确关联所选阵地。数据冻结为一个分析快照；每秒接入的新观测不会静默改写已返回卡片。卡片支持第 1、2、3 名及后续名次的地图定位，定位使用页面当前可用的对象位置；卡片证据仍保留提问时刻。处于历史回放时须先回到实时态势再提问。

“哪些最需关注”目前是距离关注排序，不等同于综合威胁或违法飞行结论。现有数据没有合法飞行授权、雷达状态/探测覆盖等事实，因此本次不提供相关问题或虚构结论。

## 本体策略与确定性指标

`ontology/attention_policy.ttl` 中声明两个带版本的排序策略，随部署写入业务 schema 命名图。后端每次读取业务 TBox 中的字段顺序；缺失或不支持的策略会拒绝分析，不让大模型补出规则。

| 策略 | 顺序 |
|---|---|
| attention-policy-v1 | 距离等级优先值 → 预计进入高关注距离圈时间 → 距离 → 无人机编号 |
| nearest-policy-v1 | 距离 → 无人机编号 |

预计时间未知时排在已知时间之后；编号用于确定性地处理同分情况。界面导入的独立学习模型不改变业务排序策略。策略变更应修改业务 Turtle 并重新发布。

Python 使用最近两条有效位置计算平均径向接近速度：`(上次到阵地的距离 - 本次距离) / 观测间隔`。预计时间为 `(本次距离 - 高关注距离阈值) / 接近速度`，仅在明显接近时计算。**该预计时间从该目标的观测时刻起算，不外推到提问时刻**；它是假设延续最近平均接近速度的线性估计，不是航线预测。已在圈内的观测记为 0；缺前次观测、间隔不足 0.1 秒或超过策略上限 30 秒、未明显接近时标记未知，不伪造时间。

过期观测、明显超前的设备时钟、缺少所选阵地评估、尚未按当前规则重新评估的对象不参与排序，并说明排除原因。不使用“观测过期”作为通信故障或雷达故障结论。

分析相关的类包括 AttentionRankingPolicy（关注排序策略）、SituationAnalysis（态势分析快照）和 RankedCandidate（排序候选记录）。候选关联原始观测、前次观测、距离评估、规则版本和排序策略，可查看本次完整 RDF / TTL 证据。

`urn:airontology:analysis` 仅保留最近一次有界分析，使用替换而非无限追加。每次最多读取 100 架当前目标，返回最多 10 名；客户端持有本次固定快照。未引入推理引擎。

## DeepSeek 的作用与配置

流式接口为 `POST /api/agent/ask`，使用 SSE（服务器发送事件）。后端先发送 snapshot（快照）和 candidate（候选卡片），再发送 explanation（解读）、notice（提示）、explanation_error（解读失败）及 done（完成）等事件。

DeepSeek 只收到固定问题、策略和后端算好的有界事实 JSON；不接受任意用户问题、任意 SPARQL 或工具调用。名次、位置、数值和可点击卡片始终来自服务器，不由模型文字生成。模型回答独立标注为生成解读，不当成新的本体事实写库。

**未配置 Key 时，名次、卡片、证据和地图联动均可运行，但明确显示“规则演示模式”，不是大模型回答。** 本次没有借用其他项目的 API Key，也没有进行真实付费模型调用。

需要真实模型解读时，在本项目 ECS 的 `/opt/airontology/shared/.env` 配置：

```dotenv
DEEPSEEK_API_KEY=在服务器本地填写自己的Key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

Key 仅进入后端容器环境，不传到前端、不写进镜像和仓库。示例 Key 值不能直接作为真实凭证使用。配置后重新部署或重建 app 容器。当前按官方 Chat Completions 接口的 SSE 协议接入，默认关闭模型思考模式，仅使用回答文本；没有启用本体推理。

每次最多输出 512 tokens，模型解读总时限 45 秒，每个后端进程最多两个并发分析；失败或提前断流会明确提示，保留已经计算的规则结果。停止按钮会中断浏览器接收；关闭窗口只收起面板，可再次打开查看已有结果。

如使用 Nginx 反向代理，参考 `deploy/nginx.conf.example` 中的流式路由：关闭响应缓冲，并设置足够的读取超时。直接使用 8092 端口无需增加代理。

## 演示与资源

模拟器默认演示 10 架无人机，每 2 秒一批，避免把原有写入频率直接放大至十架每秒。可以通过 `DEMO_TARGET_COUNT=3` 降低目标数，通过 `DEMO_INTERVAL_SECONDS` 调整间隔；间隔应低于运行配置中的数据过期阈值。ECS 仍使用原有服务，不增加数据库或本地大模型进程。

演示顺序：进入态势大屏 → 选择阵地 → 点击 AI 圆球 → 提问最需关注的无人机 → 依次点击前三名定位 → 查看本体证据 → 切到本体学习，在词典查看新策略及候选类。

本次测试覆盖策略读取、趋势和预计时间、同分排序、过期/时钟/旧规则排除、十目标卡片、DeepSeek 模拟流和错误回退、中文跨字节 SSE、卡片地图定位，以及原有 V2.1 功能。真实付费模型和线上 ECS 仍需凭证配置与部署验收。
