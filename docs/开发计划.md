# 无人机本体示例项目开发计划

日期：2026年10月21日
文档状态：开发计划，尚未实施
定位：学习 RDF/OWL 技术，通过最小业务闭环形成可演示的 WebGIS 示例项目。

## 一、总体目标

第一版走通“业务数据接入 → 本体实例更新 → 关系查询 → 地图展示”的完整链路，理解本体定义与实例事实的区别。

第二版在第一版运行稳定后，扩展多目标、多阵地、独立评估和历史回放能力。

距离计算和等级判断由 Python 完成，不引入 OWL 推理引擎。阵地统一沿用原文档中的 Position 名称。

## 二、第一版本：最小闭环演示

### 2.1 开发目标与边界

实现流程：

**模拟无人机位置 → MQTT 传输 → Python 计算距离及等级 → 更新 RDF 实例 → Fuseki 存储 → FastAPI 查询 → Leaflet 地图展示。**

| 项目 | 第一版范围 |
| --- | --- |
| 无人机 | 一架模拟无人机，持续更新位置 |
| 阵地 | 一个固定阵地 |
| 距离计算 | 根据 WGS84 经纬度计算水平距离，单位为米 |
| 等级判断 | Python 按固定距离阈值判断 |
| 数据保存 | 每个目标仅保留最新状态 |
| 地图展示 | Leaflet 二维地图 |
| 本体展示 | 中文结构列表、原始 TTL、当前实例 |
| 前端更新 | 每秒轮询一次后端接口 |
| 推理能力 | 不引入推理引擎 |

演示等级统一称为“距离关注等级”，仅用于说明阈值判断过程，不代表综合威胁判断。第一版暂不计算高度和三维斜距。

### 2.2 技术栈

| 技术 | 中文含义及用途 |
| --- | --- |
| Python | 后端开发语言，处理消息、距离计算和实例更新 |
| Mosquitto | MQTT 消息服务 |

| pyproj | 经纬度距离计算 |
| RDFLib | 创建、解析和序列化 RDF 数据的 Python 工具库 |
| RDF | 以“主语—谓语—宾语”三元组表达事实的数据模型 |
| OWL | 定义本体类别、属性等语义结构的语言 |
| RDFS | 描述名称、说明、类和属性关系的基础词汇 |
| Turtle（TTL） | RDF 数据的一种文本书写格式 |
| Fuseki | RDF 数据存储、查询和更新服务 |
| SPARQL | RDF 数据查询和更新语言 |
| FastAPI | 为前端提供 HTTP 接口的后端框架 |
| Pydantic | 校验消息报文和配置数据 |
| Vue + Leaflet.js | 页面交互与二维地图展示 |
| Docker Compose | 统一启动和管理项目服务 |

依赖版本在开发启动时统一验证并固定，不直接沿用原文中未经验证的版本组合。

### 2.3 本体模型

#### 类别定义

| 英文标识 | 中文名称 | 用途 |
| --- | --- | --- |
| BlueDevice | 无人机目标 | 表示被监测的无人机，沿用原文标识 |
| Position | 阵地 | 表示固定阵地 |
| DistanceLevel | 距离关注等级 | 表示距离分级结果 |

#### 属性与关系

| 英文标识 | 中文含义 | 类型 |
| --- | --- | --- |
| name | 名称 | 数据属性，取值为文字 |
| lon | 经度 | 数据属性，取值为数字 |
| lat | 纬度 | 数据属性，取值为数字 |
| speed | 速度，米/秒 | 数据属性，取值为数字 |
| timestamp | 最新观测时间 | 数据属性，取值为时间 |
| distanceToPosition | 到阵地距离，米 | 数据属性，取值为数字 |
| monitoredAgainst | 关联阵地 | 对象属性，关联阵地实例 |
| hasDistanceLevel | 距离关注等级 | 对象属性，关联等级实例 |

#### 等级实例与演示规则

| 实例标识 | 中文名称 | 规则 |
| --- | --- | --- |
| HighAttention | 高关注 | 距离 ≤ 100米 |
| MediumAttention | 中关注 | 100米 < 距离 ≤ 200米 |
| LowAttention | 低关注 | 200米 < 距离 ≤ 300米 |
| OutsideThreshold | 阈值外 | 距离 > 300米 |

等级定义为 DistanceLevel 类的实例，不将等级类直接当作属性取值使用。

类别、属性和关系定义属于 TBox（模型定义）；无人机001的位置、距离、等级等具体事实属于 ABox（实例数据）。等级实例属于预置的基础实例数据。

### 2.4 数据接入约定

MQTT 主题沿用原文：`counteruav/track/blue`。

```json
{
  "target_id": "drone001",
  "lon": 116.4074,
  "lat": 39.9042,
  "speed": 12.5,
  "timestamp": "2026-10-21T10:30:00Z"
}
```

| 字段 | 中文含义 | 约定 |
| --- | --- | --- |
| target_id | 目标唯一编号 | 用于生成稳定的实例标识 |
| lon | 经度 | WGS84，范围为 -180～180 |
| lat | 纬度 | WGS84，范围为 -90～90 |
| speed | 速度 | 单位为米/秒，非负有限数值 |
| timestamp | 观测时间 | ISO 8601 格式，包含时区 |

原报文中的 alt（高度）字段可以保留用于兼容，但第一版不参与计算。数字字段需拒绝非有限数值。同一目标的旧时间或重复时间报文不覆盖当前状态。

### 2.5 后端开发内容

| 模块 | 开发内容 |
| --- | --- |
| 本体初始化 | 校验并加载 TTL，将定义写入 Fuseki，初始化阵地和等级实例 |
| 模拟器 | 每秒发布一次位置，沿固定路线往返移动，覆盖各距离等级 |
| MQTT 接入 | 订阅报文、解析和校验，通过简单队列交给处理模块 |
| 距离与等级计算 | 计算水平距离，按照配置阈值判断等级 |
| 实例更新 | 更新最新位置、速度、关联阵地、距离、等级和时间 |
| 查询接口 | 提供本体结构、定义 TTL、当前态势、目标详情和实例 TTL |
| 异常处理 | 处理连接失败、写入失败、非法报文、旧报文和数据过期 |

工程约定：

- 本体定义与动态实例在 Fuseki 中分开管理，使用不同命名图。
- 使用持久化数据集，保留服务重启前的数据。
- 静态 TTL 是本体初始化来源，不作为实时位置文件反复改写。
- 初始化采用幂等方式；本体初始化失败时明确报错并停止业务启动。
- RDF 字面量通过工具库构造，避免直接拼接未经处理的消息内容。
- 更新完成后再通过查询接口对外展示，地图与实例面板读取同一数据来源。
- 默认超过5秒未收到有效新观测标记为“数据过期”，阈值可配置；过期不等于实际确认目标失联。

### 2.6 前端开发内容

页面布局采用“地图 + 目标详情侧栏 + 本体查看面板”。

| 区域 | 功能 |
| --- | --- |
| 地图 | 展示阵地、无人机、二者连线和距离分级参考圈 |
| 状态展示 | 使用颜色区分等级，显示最后更新时间及数据过期状态 |
| 目标详情 | 点击无人机查看中文属性、位置、速度、关联阵地、距离和等级 |
| 本体结构 | 按中文列出类、数据属性和对象属性，同时显示英文标识 |
| 本体 TTL | 查看静态本体定义，支持复制，第一版只读 |
| 当前实例 | 中文属性表与实例 TTL 两种视图，随最新数据更新 |

学习展示重点：将“地图对象 → 中文业务属性 → RDF 三元组”对应起来，不开发复杂的三维本体关系图。

坐标约定：数据统一使用 WGS84；Leaflet 坐标输入采用纬度、经度顺序，注意与消息字段排列的区别。底图地址通过配置提供，保留必要署名，并在联调时确认演示环境可访问。

### 2.7 接口计划

| 接口 | 用途 |
| --- | --- |
| GET /api/health | 检查后端及 MQTT、Fuseki 依赖状态 |
| GET /api/ontology | 获取本体结构及中文名称、说明 |
| GET /api/ontology/ttl | 获取静态本体定义 TTL |
| GET /api/situation | 获取阵地及无人机最新态势 |
| GET /api/targets/{id} | 获取指定无人机详情 |
| GET /api/targets/{id}/ttl | 获取该无人机最新实例 TTL及必要的关联信息 |

结构化接口返回 JSON；TTL 接口返回 Turtle 文本。接口字段、时间格式和错误格式在开发时统一约定。

### 2.9 实施顺序与预计安排

暂按5～7个开发日估算，实际随运行环境和联调情况调整。

| 阶段 | 工作 | 完成标志 |
| --- | --- | --- |
| 第1天 | 修正本体模型，用 RDFLib 创建、序列化并查询示例实例 | 能解释模型定义与实例事实 |
| 第2天 | 接入持久化 Fuseki，实现更新和查询 | 新数据可以替换旧状态 |
| 第3天 | 完成模拟器、MQTT 接入、校验和计算 | 消息自动变成最新实例事实 |
| 第4天 | 完成 FastAPI 接口及 Leaflet 地图 | 地图随最新实例变化 |
| 第5天 | 完成本体查看、中文详情和过期状态 | 可对照地图与 RDF 数据 |
| 第6～7天 | 联调、必要测试、启动配置和演示文档 | 可重复启动并完成演示 |

### 2.10 验收标准

1. 按文档启动服务和模拟器，无需手工修改代码。
2. 地图显示一个固定阵地和一架持续移动的无人机。
3. 距离跨越100米、200米、300米边界时，数值、等级和颜色正确变化。
4. 点击无人机能查看最新属性及关联阵地。
5. 本体面板能查看中文结构、本体定义 TTL 和当前实例 TTL。
6. 同一目标重复更新后，只保留一套最新位置、距离和等级。
7. 旧报文、重复报文和非法报文不会覆盖有效最新状态。
8. 停止模拟器后，页面按配置阈值显示数据过期。
9. 服务重启后，Fuseki 数据仍保留，初始化不产生重复业务对象。
10. 对距离边界、状态替换和时间顺序进行必要验证，并完成一轮端到端演示。

### 2.11 交付物与演示流程

交付物：前后端源码、OWL本体定义TTL、预置实例TTL、模拟器、Docker Compose配置、环境配置样例、启动说明及演示说明。

建议演示顺序：

1. 查看本体结构，说明“无人机、阵地、等级”及其关系。
2. 查看原始 TTL，对照中文名称理解类和属性。
3. 启动模拟器，展示地图目标移动和距离等级变化。
4. 点击目标，对照业务属性与最新实例 TTL。
5. 停止模拟器，展示数据过期状态。

## 三、第二版本：业务能力扩展（简版）

| 方向 | 简要计划 |
| --- | --- |
| 多目标、多阵地 | 支持多架无人机与多个阵地，分别建立评估关联 |
| 独立评估模型 | 新增 Assessment（评估记录）类，记录目标、阵地、距离、等级及时间，避免多阵地结果混淆 |
| 历史与回放 | 保存观测和评估历史，支持时间查询和轨迹回放；根据规模确定历史存储方式 |
| 配置管理 | 页面维护阵地和距离阈值，记录规则版本 |
| 实时推送 | 根据实际频率和规模，引入 WebSocket（实时双向通信）推送 |
| 本体关系展示 | 增加对象关系图，点击地图对象可查看关联链路 |

第二版继续采用“Python计算和判断、本体表达和查询”的分工，不要求学习或引入 OWL 推理。第一版验收后再细化第二版排期。

## 四、术语速查

| 术语 | 中文理解 |
| --- | --- |
| 类 | 一类对象，例如无人机、阵地 |
| 实例 | 某个具体对象，例如无人机001、一号阵地 |
| 数据属性 | 对象与文字、数字、时间等具体值之间的联系 |
| 对象属性 | 对象与另一个对象之间的关系 |
| 三元组 | 用“主语—谓语—宾语”表达一条事实 |
| TBox | 描述类别、属性和关系等模型结构 |
| ABox | 描述具体对象及其属性和关系事实 |
| rdfs:label | 中文名称或其他语言的显示名称 |
| rdfs:comment | 解释说明文字 |
| @zh | 表示这段文字为中文 |
| cu: | 本项目自定义业务名称的前缀简写 |

阅读和编写本体时，英文标识同时配备中文名称和必要说明，降低理解成本。
