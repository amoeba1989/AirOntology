# 规则引擎第一版 · v2.5.0

入口 `/rules`。原“阵地与规则配置”入口已统一为规则引擎，阵地和原距离分级在“对象与距离配置”中维护。

## 支持范围

| 类型 | 输入 | 结果 |
| --- | --- | --- |
| 内置距离分级 | 目标位置、阵地、原有三级阈值 | 继续用于地图等级及历史评估 |
| 观测过期 | 无人机最后观测时间 | 超时提醒、恢复上报 |
| 雷达上报中断 | 模拟设备台账中雷达最后状态时间，可按部署阵地筛选 | 上报中断提醒、恢复上报；不判断物理设备故障 |
| 圆形区域进出 | 当前阵地中心、半径、有效无人机位置 | 首次确认在区域内、进入、离开、无法判断 |

新增规则默认停用，需填写依据、启用并发布。当前雷达模板使用 `/api/devices` 台账和状态，尚不消费多源证据接口中单独登记的传感器；不存在实际探测、目标关联或控制动作。

规则引擎不会更改现有地图的距离分级。区域规则半径与地图距离圈独立；第一版的区域结果在“运行与证据”中展示，尚未叠加专属区域到地图。

## 操作流程

1. 在“规则库与编辑”左侧选择模板。填写名称、依据、适用阵地及阈值。
2. 勾选“发布后启用”。停用规则不参加试运行或后台执行。
3. 点击“试运行草稿”，查看命中、未命中和无法判断。可选择过去的单一快照时间。
4. 填写发布说明，发布全部草稿。后台约每5秒执行一轮（处理时间另计），无需保持页面打开。
5. 查看“运行与证据”：当前结果包含实际输入、来源、规则参数和规则集版本；事件只在状态变化时生成。
6. “发布版本”可将旧版载入恢复草稿，重新试运行、发布；不会直接覆盖线上状态。

试运行是只读快照评估，不执行历史连续事件回放，不生成进入/离开事件。历史只包括仍保留的无人机观测和当时评估关联的阵地坐标；雷达历史不支持。清空时间使用当前事实。编辑草稿后需重新试运行查看新结果。

## 状态与证据语义

- 命中：本条条件成立；不代表黑飞、威胁或物理设备故障。
- 未命中：有效输入不满足本条条件。
- 无法判断：缺少输入、时间超前、位置过期、阵地不存在或不支持的历史数据。
- 初次读到区域内对象仅记录“首次确认”，不伪造从外部进入的过程。
- 数据过期、采样/观测间隔超过规则有效期、发布新版本、对象配置版本变化后，重新建立基线，不跨空档推断离开。
- 未命中仅表示本次有效快照在圆形区域外；不证明两次采样之间未进入。
- 同一状态不重复产生事件；发布新版本重新建立基线，因此可能产生新版本的首次确认。

## 存储与运行

规则集、最近20个发布版本、最近300条事件和最新运行状态以结构化 JSON 字面量保存在 Fuseki 命名图 `urn:airontology:rules`。事件包含参数、输入与配置版本快照，不依赖当前参数解释过去结果。第一版尚未将新事件展开为本体拓扑中的独立 RDF 关系。

版本恢复仅涉及新增规则集，不恢复对象/距离配置。实时状态重启后保留；若间隔超过有效期，空间事件重新建立基线。内存预览模式重启清空所有数据。

当前部署应继续使用单应用进程、单副本（现有 Dockerfile 为 `--workers 1`）。进程内锁和期望版本避免并发覆盖；扩容多副本前需要数据库级版本比较、领导者选举或独立调度服务。

## 接口

- `GET /api/rules`：发布内容、版本、结果、事件及引擎状态。
- `PUT /api/rules`：发布整个规则集；`expected_revision` 不匹配返回409。
- `POST /api/rules/trial`：只读试运行；`at` 为带时区历史时间，可省略。
- `GET/PUT /api/config`：原有对象与距离配置接口，保持兼容。

发布示例（先 GET 获取当前版本号和真实阵地编号）：

```json
{
  "expected_revision": 0,
  "note": "增加演示区域提醒",
  "rules": [{
    "id": "zone-demo",
    "name": "甲阵地圆形关注区",
    "kind": "zone",
    "enabled": true,
    "source": "演示假设；300米为示例参数，不是行业标准",
    "position_id": "pos001",
    "seconds": 30,
    "radius": 300
  }]
}
```

## 版本维护

前端构建读取 `frontend/package.json` 版本，后端读取 `backend/app/version.py`。迭代功能时同步更新这两处及 `frontend/package-lock.json`，后端测试会验证两端版本一致。系统右下角显示前端版本；两端不同会提示后端版本，后端不可访问则明确显示未确认。

## 后续扩展

持续停留与迟到事件处理、多边形/高度区域、授权记录匹配、按来源适配真实设备状态、规则冲突分析、完整历史重算和地图/本体事件联动均不包含在第一版。
