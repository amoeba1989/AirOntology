# 本体学习说明

## 先看业务，再看语法

本项目描述：无人机001关联一号阵地，程序计算二者水平距离，并记录距离关注等级。

- **模型定义**：有“无人机目标”“阵地”“距离关注等级”三个类别，有位置、距离等属性及关联阵地等关系。
- **实例事实**：无人机001是无人机目标，它的位置是多少、关联哪个阵地、当前距离和等级是多少。

RDF是三元组数据模型；OWL用于定义本体语义；TTL是文本格式；Fuseki提供存储和查询服务；SPARQL用于查询和更新。Python负责本项目的距离计算与等级判断。

## 对照一段代码

```turtle
@prefix cu: <http://counteruav.org/counterUav#> .
@prefix owl: <http://www.w3.org/2002/07/owl#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .

# 类别定义
cu:Position a owl:Class ;
    rdfs:label "阵地"@zh .

# 数值属性定义
cu:distanceToPosition a owl:DatatypeProperty ;
    rdfs:label "到阵地水平距离（米）"@zh ;
    rdfs:range xsd:double .

# 以下仅演示实例语法，不表示完整的实时记录
cu:pos001 a cu:Position ;
    rdfs:label "一号阵地"@zh .
```

| 写法 | 中文含义 |
| --- | --- |
| @prefix | 声明名称前缀的简写 |
| cu: | 我们自己定义的业务名称前缀，可换名但需保持声明一致 |
| a | rdf:type的简写，表示“是……的实例” |
| owl:Class | 类 |
| owl:ObjectProperty | 对象属性，连接对象与另一个对象 |
| owl:DatatypeProperty | 数据属性，连接对象与数值、文字等 |
| owl:NamedIndividual | 有名字标识的实例 |
| rdfs:label | 供人阅读的名称 |
| rdfs:comment | 说明文字，不是可执行计算规则 |
| rdfs:domain | 属性定义域，具有语义含义，不替代输入校验 |
| rdfs:range | 属性值域，具有语义含义，不替代输入校验 |
| xsd:double | 双精度浮点数 |
| xsd:dateTime | 日期时间类型 |
| @zh | 前面的文字为中文 |
| 分号 ; | 主语不变，继续描述同一对象 |
| 句号 . | 语句结束 |

## 在页面中学习

1. 看“中文结构”，先认识类和两类属性。
2. 切换“本体定义TTL”，找到相同英文标识和中文label。
3. 观察地图，等待距离和等级变化。
4. 切换“当前实例TTL”，找到位置、距离、阵地和等级。
5. 对照理解：静态定义没有随位置变化，变化的是实例事实。

本项目不需要学习推理。OWL文件中只使用基础定义；没有配置推理器，也不宣称OWL会自动判断距离等级。

## 手动查询示例

以下查询在Fuseki的`/counteruav/query`接口执行，注意本项目使用命名图。

```sparql
PREFIX cu: <http://counteruav.org/counterUav#>
SELECT ?target ?distance ?level
WHERE {
  GRAPH <urn:airontology:state> {
    ?target a cu:BlueDevice ;
            cu:distanceToPosition ?distance ;
            cu:hasDistanceLevel ?level .
  }
}
```

中文意思：在最新状态图中，查出无人机目标及其距离、等级。

## 第二版：把观测和评估分开

第二版新增三个类：Observation（观测记录）、Assessment（评估记录）、DistanceRule（距离规则）。下面是简化的实例片段，使用前文的cu、xsd前缀：

```turtle
# 无人机001当前关联一条最新观测和两条评估。
cu:drone001 a cu:BlueDevice ;
    cu:latestObservation cu:obs_example ;
    cu:latestAssessment cu:eval_one, cu:eval_two .

# 观测记录表达设备上报的事实。
cu:obs_example a cu:Observation ;
    cu:ofTarget cu:drone001 ;
    cu:lon "116.4074"^^xsd:double ;
    cu:lat "39.9042"^^xsd:double ;
    cu:source "模拟器" .

# 第一条评估明确对应一号阵地。
cu:eval_one a cu:Assessment ;
    cu:ofTarget cu:drone001 ;
    cu:toPosition cu:pos001 ;
    cu:basedOnObservation cu:obs_example ;
    cu:usedRule cu:rule_example ;
    cu:distanceToPosition "80.0"^^xsd:double ;
    cu:hasDistanceLevel cu:HighAttention .

# 第二条评估明确对应二号阵地。
cu:eval_two a cu:Assessment ;
    cu:ofTarget cu:drone001 ;
    cu:toPosition cu:pos002 ;
    cu:basedOnObservation cu:obs_example ;
    cu:usedRule cu:rule_example ;
    cu:distanceToPosition "500.0"^^xsd:double ;
    cu:hasDistanceLevel cu:OutsideThreshold .
```

80米和500米只是语义示例，不是由片段中的经纬度计算出的数值。实际运行会保存完整时间、规则阈值和阵地坐标等依据。

逐条读成中文：无人机001有一条观测；这条观测分别针对两个阵地产生两条评估；每条评估明确采用哪版规则并得到自己的距离和等级。

页面“查看评估”正是沿这些对象关系查询数据，而不是让大模型临时猜测判断依据。

第二版查询示例：

```sparql
PREFIX cu: <http://counteruav.org/counterUav#>
SELECT ?target ?assessment ?position ?distance ?observation ?rule
WHERE {
  GRAPH <urn:airontology:state> {
    ?target cu:latestAssessment ?assessment .
  }
  GRAPH <urn:airontology:history> {
    ?assessment cu:toPosition ?position ;
                cu:distanceToPosition ?distance ;
                cu:basedOnObservation ?observation ;
                cu:usedRule ?rule .
  }
}
```

前文第一版“在无人机上直接查询距离”的示例仅适用于旧数据；第二版应使用上述独立评估查询。
