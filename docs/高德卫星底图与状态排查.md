# 高德卫星底图与设备状态排查

## 启用卫星底图

项目继续用 Leaflet 画阵地、无人机、轨迹与距离圈；高德 JS API 2.0 提供底层在线卫星影像。浏览器需要能访问高德地图服务。

1. 在高德开放平台创建 **Web 端（JS API）** key，按实际访问域名配置白名单，并获取对应的安全密钥。ECS 公网访问时使用实际域名或公网 IP 对应的合法配置；请遵循开放平台控制台要求和服务条款。
2. 在 ECS `/opt/airontology/shared/.env` 填入 `AMAP_JS_KEY=...` 和 `AMAP_SECURITY_JS_CODE=...`。安全密钥仅保存在 ECS；页面取得公开的 JS key，请勿把安全密钥写进 `VITE_` 变量或前端代码。后端同源转发高德安全服务请求。
3. 从已部署的 release 目录以同一组 `--env-file` 重建 app 容器；或者在下一次自动部署时由新 release 读取同一份 `shared/.env`。底图配置是运行时变量，改密钥无需重新构建前端。

若未配置或加载失败，地图显示标准底图并提示原因，叠加的业务对象仍可操作。业务记录和距离计算仍使用 WGS84；仅卫星图上的位置转换为高德使用的 GCJ-02。卫星图来自在线服务，演示请保持联网。iconfont 图标素材应下载到仓库并记录素材作者与许可，不能仅凭 iconfont 平台名称推断所有图标都可自由商用。

## 为什么出现“数据过期”或“signal timed out”

- “数据过期”比较**观测消息发布时间**与当前时间。之前默认阈值仅 5 秒；现在旧默认配置会升级到 30 秒，手动设定过阈值的配置不会覆盖。停掉模拟器、MQTT 中断、写入失败、ECS 时间偏差，都会让数据真的变旧；不会把旧数据伪装成实时。
- “设备状态读取失败：signal timed out”表示浏览器访问 `/api/devices` 等待超过 15 秒。旧版模拟器逐架写 Fuseki，并让读取等整帧写完；小规格 ECS 上容易触发。这不是页面操作失误。新版将同一帧航迹合并提交、积压时保留最新帧、设备读取不等整帧锁，轮询频率也降低了。提示会显示最近一次成功读取时间。

复现时先看 `/api/health` 的 `fuseki`、`mqtt.connected`、`mqtt.last_write`、`mqtt.last_error`、`mqtt.frame_pending` 和 `mqtt.superseded_frames`。若 `last_write` 长时间不变化，检查模拟器、MQTT 和 app 日志。若模拟器仍在发送、但 Fuseki 频繁超时，先将 ECS 的 `DEMO_TARGET_COUNT` 降至 6～10、`DEMO_INTERVAL_SECONDS` 调至 3～5，再观察 CPU、内存与磁盘；长期运行可提高 ECS 内存并清理旧 Docker 镜像。历史观测保留期限由 `HISTORY_LIMIT` 管理。
