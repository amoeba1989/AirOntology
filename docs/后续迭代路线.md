# 本体学习与业务迭代路线

本次增加：每架无人机最近最多 300 个观测点的实时轨迹；历史回放只画截至当前帧的轨迹；断报超过 max(10 秒, 过期阈值两倍) 时断开。初始化尝试读取服务器历史，后续追加实时观测。单点不形成线段。

无人机使用圆形四旋翼图标，阵地使用方形旗标。距离圈增强线宽、填充与半径标签，支持显示开关，定位全景包含最大距离圈。轨迹颜色区分目标；图标颜色表示相对选中阵地的距离分级。距离圈不代表禁飞区或综合威胁结论。

| 顺序 | 业务功能 | 学习技术 | 验收示例 |
|---|---|---|---|
| 1 | RDF 数据质量检查 | SHACL（形状约束语言）、pySHACL | 缺少时间、评估关联多个阵地时显示中文错误 |
| 2 | 中文问题与查询对照 | SPARQL（RDF 查询语言） | 预设只读查询展示语句、结果和地图高亮 |
| 3 | 区域与进出事件 | GeoSPARQL（地理语义查询标准）、GeoJSON（地理数据格式）、Shapely（Python 几何计算库） | 绘制区域，记录进入及离开；先以 Python 计算，再验证 Fuseki 的地理查询配置与能力 |
| 4 | 任务、授权与来源 | OWL 类与关系、PROV-O（来源本体） | 无人机关联任务及有时效的授权，事件关联观测、来源、时间、规则版本 |
| 5 | 业务数据库接入 | Ontop（虚拟知识图谱）、R2RML（关系数据库到 RDF 的映射） | 有实际业务表后，将任务、设备数据映射为 RDF，通过 SPARQL 查询 |
| 6 | 带证据的中文问答 | 大语言模型结合知识图谱、受控只读工具 | 回答附观测与规则链接，不依赖模型直接给出业务判断 |

现有 RDF/OWL、RDFLib、Fuseki、SPARQL 是基础。优先补数据约束和查询，再做区域事件与业务关系；无需同时增加推理引擎或另一套图数据库。OWL 描述类与关系，SHACL 检查图数据，Python 负责距离与几何计算。
